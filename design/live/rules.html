This repo, .reverie/context

  1. Ledger entries are append-only: corrections are new reversing entries, never UPDATE or DELETE, because auditors replay the table.

    paths-services-ledger.mdonly under services/ledger/**Open rule

  2. Money is stored and passed as integer minor units (cents) with an ISO 4217 currency code; never use floats, because rounding drift broke reconciliation in the March settlement run.

    rules.mdOpen rule

  3. Every endpoint that creates a charge or refund must require an Idempotency-Key header and store the response for 24 hours, because card-network retries otherwise double-charge.

    rules.mdOpen rule

  4. Database migrations must be backward compatible with the previous release, because we deploy with rolling restarts and alembic runs before the new pods are ready.

    rules.mdOpen rule

  5. Use app/clients/ledger.py for all ledger writes; do not call the ledger service directly from handlers, because it owns retry and outbox semantics.

    Possibly outdatedrules.mdOpen rule

  6. Log payment identifiers (payment_id, merchant_id) but never card numbers, CVV or full bank account numbers, because logs ship to a third-party aggregator.

    rules.mdOpen rule

  7. Secrets come from the secrets manager through app/config.py; never read them from environment files committed to the repo, because we rotate them quarterly.

    security.mdOpen rule

  8. Webhook payloads from the card processor must be verified with verify_signature() in app/webhooks/verify.py before any parsing.
